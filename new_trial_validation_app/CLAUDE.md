# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This is the **new** Laravel app replacing the legacy PHP app at the repo root (`../`). See `../CLAUDE.md` and `../MIGRATION_PLAN.md` for the overall migration plan, phase checklist, and SSO bridge design — this file only covers commands/architecture local to this Laravel codebase.

## Commands

```bash
composer run dev      # php artisan serve + queue:listen + vite dev, all concurrently
composer run lint      # pint --parallel (auto-fix)
composer run lint:check   # pint --parallel --test (check only)
composer run types:check  # phpstan analyse (larastan)
composer run test      # config:clear + lint:check + types:check + php artisan test
composer run ci:check   # npm lint:check + npm format:check + npm types:check + test

php artisan test                                  # full Pest/PHPUnit suite
php artisan test --filter=TestName                # single test by name
php artisan test tests/Feature/DashboardTest.php   # single file

npm run dev          # vite dev server (frontend only, use alongside `php artisan serve` if not using composer run dev)
npm run build         # vite build (add build:ssr for SSR build)
npm run lint          # eslint --fix
npm run format         # prettier --write resources/
npm run types:check      # tsc --noEmit
```

Tests use **Pest** (`tests/Pest.php`), not raw PHPUnit syntax, even though `phpunit.xml` configures the runner.

## Architecture

Official `laravel/react-starter-kit` scaffold — **Inertia.js**, not a decoupled REST API + SPA. Pages are server-rendered React components returned via `Inertia::render()` from controllers in `app/Http/Controllers`; there is no client-side router fetching JSON from a separate API for these pages.

- `resources/js/pages/` — Inertia page components (one per route), grouped by feature (`auth/`, `settings/`).
- `resources/js/layouts/` — shared layout shells (`app/`, `auth/`, `settings/`).
- `resources/js/components/ui/` — shadcn/Radix UI primitives.
- `resources/js/routes/` and `resources/js/actions/` — **generated by Laravel Wayfinder** (`laravel/wayfinder` + `@laravel/vite-plugin-wayfinder`), giving typed TS helpers for Laravel routes/controller actions. Don't hand-edit these — they regenerate from PHP routes/controllers on build.
- `app/Actions/Fortify/` — Laravel Fortify handles auth actions (registration, password reset, etc.); `app/Providers/FortifyServiceProvider.php` wires it up.
- `routes/web.php` / `routes/settings.php` — current routes are all Fortify/starter-kit boilerplate (profile, security settings) — no trial-validation domain routes exist yet.
- `boost.json` / `.mcp.json` — Laravel Boost is configured, providing MCP tools for this Laravel app (schema/route/log introspection etc.) when available in this session.

### Not yet built

No domain code from the legacy app has been ported yet — no trial/review/approval models, controllers, or migrations beyond the starter kit's own `User` model. When starting Fase 1 work (see `../CLAUDE.md`), this is a clean slate for the admin/master-data modules.

### Reconciling with MIGRATION_PLAN.md

`../MIGRATION_PLAN.md` §5 was drafted assuming a pure JSON API (Sanctum token/cookie auth + API Resources) for *every* screen, to keep the web and future mobile app on the same contract. This scaffold being Inertia-based changes that for the web side:

- Web pages → `Inertia::render()` from normal controllers, authenticated via standard Laravel session (Fortify) — this is actually simpler than the original plan's cookie-based Sanctum SPA setup, and the SSO bridge design (ticket → `Auth::login()`) still applies unchanged.
- Mobile app (Fase 4+) will still need a separate `/api/v1/*` namespace with Sanctum **token** auth and API Resources, since Inertia responses aren't consumable by a mobile client.

This hasn't been confirmed with the user yet — flagged in `../CLAUDE.md`.
